After [creating a recording](/record-and-playback/recording/), you can replay it by loading the file into a mock
server with
[`MockServer::playback`](https://docs.rs/httpmock/latest/httpmock/struct.MockServer.html#method.playback):

```rust
// ...

// Save the recording to
// "target/httpmock/recordings/github-torvalds-scenario_<timestamp>.yaml".
let target_path = recording
    .save("github-torvalds-scenario")
    .expect("cannot store scenario on disk");

let playback_server = MockServer::start();

// Play back the recorded interactions from the file.
playback_server.playback(target_path);
```

`playback` reads the file and creates one mock per recorded interaction, as if you had configured them with
[`MockServer::mock`](https://docs.rs/httpmock/latest/httpmock/struct.MockServer.html#method.mock): the recorded
request becomes the [`When`](https://docs.rs/httpmock/latest/httpmock/struct.When.html) part, the recorded
response the [`Then`](https://docs.rs/httpmock/latest/httpmock/struct.Then.html) part. Whenever the server then
receives a request that matches one of the recorded requests, it answers with the corresponding recorded
response. If the recording was made with `record_response_delays(true)`, the response is delayed by the
recorded duration.

The method returns the set of mocks it created, so you can delete them again or assert on them like any other
mock. Playback is available with the `record` cargo feature.

Recording files are plain YAML in the same format as the
[static mock files](/server/standalone/) a standalone server loads, so you can also check them into your
repository and edit them by hand.
