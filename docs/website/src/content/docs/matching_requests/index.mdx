---
title: Matching Requests
description: How the When part of a mock decides which requests it answers, and where to find every matcher in the API reference.
---

Every mock has a `when` part. Each method you call on it adds one criterion, and the mock only answers a request if every criterion holds. A request that matches no mock at all gets a `404 (Not Found)` from the mock server. If you want to know why a mock did not fire, call [`Mock::assert`](https://docs.rs/httpmock/latest/httpmock/struct.Mock.html#method.assert) on it: its failure message lists the closest request and which criteria failed. All matcher methods return the [`When`](https://docs.rs/httpmock/latest/httpmock/struct.When.html) builder again, so they chain, and you can combine criteria from different groups freely: a `method`, a `path_prefix` and a `header` on one mock mean all three have to hold.

The methods follow one naming scheme across all request parts. The plain name (`path`, `header`, `cookie`) requires an exact match. `_not` requires that the value is not equal, `_includes` and `_excludes` look for a substring, `_prefix` and `_suffix` check the start and end of a value, `_prefix_not` and `_suffix_not` are their negations, and `_matches` takes a regular expression. Key-value parts such as query parameters, headers, cookies and form fields also have `_exists` and `_missing`, which only look at the name, and `_count`, which checks how many pairs match a pair of regular expressions.

Case sensitivity depends on the part. Scheme, method and host are compared case-insensitively, as the respective standards require. The request body is compared byte by byte, so body matchers are case-sensitive since version 0.8 (0.7 and earlier compared bodies case-insensitively).

Each method has its own example in the API reference on docs.rs, so this page only maps the groups and links to them. If the built-in matchers are not enough, [custom matchers](/matching_requests/custom/) let you run your own function against the request.

## Any request

[`any_request`](https://docs.rs/httpmock/latest/httpmock/struct.When.html#method.any_request) adds no criterion at all and exists to make it explicit that a mock answers everything. A `when` you never call a method on behaves the same way.

## Method

The HTTP method accepts a string such as `"GET"` or a [`Method`](https://docs.rs/httpmock/latest/httpmock/enum.Method.html) variant, and is compared case-insensitively.

- [`method`](https://docs.rs/httpmock/latest/httpmock/struct.When.html#method.method)
- [`method_not`](https://docs.rs/httpmock/latest/httpmock/struct.When.html#method.method_not)

## Query parameters

Query parameter matchers take a name and a value, except for `_exists` and `_missing`, which only take the name, and `_count`, which takes two regular expressions and the expected number of matching pairs. A parameter that appears several times is matched if any of its values satisfies the criterion.

- [`query_param`](https://docs.rs/httpmock/latest/httpmock/struct.When.html#method.query_param)

### JSON bodies

The JSON matchers parse the body and compare values instead of text, so key order and formatting do not matter. `json_body` takes a `serde_json::Value` (the `json!` macro is the usual way to build one), `json_body_obj` takes any type that implements `Serialize`, and `json_body_includes` and `json_body_excludes` check whether a partial JSON document is contained in the body.

- [`json_body`](https://docs.rs/httpmock/latest/httpmock/struct.When.html#method.json_body)

- [`json_body_excludes`](https://docs.rs/httpmock/latest/httpmock/struct.When.html#method.json_body_excludes)

## Scheme

The scheme is `http` or `https` and is compared case-insensitively. It is only useful with the `https` feature or when proxying, since a plain mock server only ever receives `http` requests.

- [`scheme`](https://docs.rs/httpmock/latest/httpmock/struct.When.html#method.scheme)
- [`scheme_not`](https://docs.rs/httpmock/latest/httpmock/struct.When.html#method.scheme_not)

## Reusing criteria

[`and`](https://docs.rs/httpmock/latest/httpmock/struct.When.html#method.and) applies a function `fn(When) -> When` inside a chain, so a set of criteria that several mocks share can live in one helper and still read as part of the chain. [`is_true`](https://docs.rs/httpmock/latest/httpmock/struct.When.html#method.is_true) and [`is_false`](https://docs.rs/httpmock/latest/httpmock/struct.When.html#method.is_false) run your own closure against the request; see [custom matchers](/matching_requests/custom/).
